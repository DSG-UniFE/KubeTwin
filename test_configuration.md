## Installation and Configuration

To install all the ruby dependencies gems, run the following command:
```bash
bundle install
```
KubeTwin also needs some python dependencies to load the MDN files. 
Create a virtual environment and install the dependencies with the following commands:
```bash
pip install -r requirements.txt
```
## Configuration File

To run the comparison, first modify the configuration file `comparison.conf`
You can find this file in the project root directory. The file is very simple and contains the following fields:

```ruby
config_file: "examples/cuttlefish.conf"
k8s_log_files: "/Users/filippopoltronieri/Downloads/batch_models/metrics-sd1/ttr_rep4.0_sd1.0"
```

The `config_file` field contains the path to the configuration file used by the simulator. Here, what you need to modify are the mdn_file parameter of each microservice type. This parameter represents the path to the MDN directories. I suggest to copy the MDN dirs inside the KubeTwin's root directory. 

The `k8s_log_files` field contains the path to the directory containing the log files generated by the Kubernetes cluster. Specify the absolute path to this directory so the comparison script can reproduce the request timing.

## Run the comparison script

The comparison script is `bin/log_compare`. The only parameter to modify is the number of replica per microservice and you can find it at line 125. 

Once you have modified the configuration file, run the comparison script with the following command:
```bash
bundle exec ruby bin/log_compare
```
The script will rename the log files with the correct name and will generate the comparison results in the main  directory.
